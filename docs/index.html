System Architecture & Lifecycle

PortGrid runs as a lightweight daemon communicating directly with the local Docker daemon over the Unix domain socket (/var/run/docker.sock). Unlike conventional script wrappers, PortGrid enforces deterministic state through an internal orchestration engine:

PORTGRID DETERMINISTIC CONTROL FLOW
[1] USER INVOCATION Developer runs "portgrid up" or triggers deployment via Web Console (:3000)
[2] PORT ARBITRATION PortGrid scans host ephemeral ports; validates 5432, 6379, 9092 against collision matrix
[3] SECRET DERIVATION PBKDF2 derivations generate unique instance passwords stored in AES-256-GCM vault
[4] CONTAINER SPAWN Docker API launches primary engine and paired companion UI with isolated bridge network
[5] MERKLE LOG ENTRY SHA-256 state hash calculated with previous block parent hash and written to audit ledger

Frequently Asked Questions

Does PortGrid replace Docker Desktop or OrbStack?

No. PortGrid uses your existing Docker engine (Docker Desktop, OrbStack, Colima, or Linux dockerd) to run containers. It eliminates the fragile YAML scripts and port collision headaches usually associated with managing complex local stacks.

Are container volumes persistent across reboots?

Yes. All database schemas, Kafka topics, and Jenkins pipelines are stored in named Docker volumes prefixed with portgrid_data_*. When you run portgrid down and later portgrid up, all data is retained intact.

Is PortGrid free for commercial use?

Yes. PortGrid is 100% open source under the Apache 2.0 license. You can use it freely in personal projects, startups, and large enterprise environments without licensing fees.

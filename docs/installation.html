PORTGRID DEPLOYMENT GUIDE

Installation & Setup

PortGrid is designed to boot in under five seconds on any developer workstation or dedicated CI/CD agent. Choose the deployment method that fits your environment, from zero-install NPX to air-gapped enterprise tarballs.

1 System Prerequisites

Before launching PortGrid, ensure your host environment meets these baseline requirements:

CONTAINER RUNTIME
Docker Engine 24.0+

Compatible with Docker Desktop, OrbStack (macOS), Colima, or native Linux dockerd with accessible /var/run/docker.sock.

NODE RUNTIME
Node.js 18.0.0+ LTS

Required for CLI operation (NPM or NPX). Containerized deployment modes require zero local Node.js installation.

PORT ALLOCATION
Ports 3000 & 4000

Port 3000 hosts the Web UI console; port 4000 hosts the orchestrator daemon. Both can be configured via environment flags.

2 Option A: Global NPM Installation (Recommended)

Install the PortGrid CLI globally across your operating system for persistent shell access:

bash / zsh terminal global installation 
# 1. Install PortGrid CLI globally from npm registry
npm install -g @portgrid/cli

# 2. Boot the orchestrator and launch the web console
portgrid up

# Web console launches automatically at http://localhost:3000

3 Option B: Zero-Install Instant Run via NPX

Run PortGrid immediately without modifying global system node_modules packages:

bash / zsh terminal zero install mode 
# Pull and execute the latest verified binary directly
npx @portgrid/cli up

4 Option C: Homebrew Package (macOS & Linux)

For native Apple Silicon / Intel macOS and Linuxbrew users: 

# Tap the official PortGrid distribution repository
brew tap mannasuman134/tap

# Install the formula
brew install portgrid

# Start as background daemon or interactive CLI
portgrid up --daemon

5 Option D: Standalone Containerized Mode

Run PortGrid entirely inside an isolated container with mounted host Docker daemon access: 

# Run PortGrid container with host socket passthrough
docker run -d \
  --name portgrid-orchestrator \
  --restart unless-stopped \
  -p 3000:3000 \
  -p 4000:4000 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v portgrid_data:/root/.portgrid \
  portgrid/portgrid:latest

6 Option E: Air-Gapped & Enterprise Offline Bundle

For sovereign enclaves, defence environments, and air-gapped financial networks where public registry access is blocked: 

# 1. On an internet-connected workstation, download the self-contained bundle
curl -O https://github.com/mannasuman134/portgrid/releases/download/v1.2.3/portgrid-enterprise-offline.tar.gz

# 2. Transfer tarball to the air-gapped machine via approved medium
# 3. Extract and load all pinned immutable container images into local Docker cache
tar -xzf portgrid-enterprise-offline.tar.gz
cd portgrid-enterprise-offline
./load-images.sh

# 4. Launch with internal registry mirroring enabled
./portgrid up --offline --vault-key /secure/vault.key

7 Health & Diagnostics Verification

Verify the orchestrator is correctly connected to your Docker daemon and that all cryptographic components are initialized:

8 Troubleshooting & Common Questions

ISSUE: Cannot connect to Docker daemon

Occurs if Docker Desktop or OrbStack is not running, or if permissions on /var/run/docker.sock are restricted to root.

sudo usermod -aG docker $USER && newgrp docker

ISSUE: Port 3000 or 4000 already in use

You can specify alternative port bindings using the CLI flags or environment variables:

portgrid up --ui-port 3030 --api-port 4040

ISSUE: Pull failures on corporate TLS proxy

Configure PortGrid to use an internal Artifactory or Harbor image registry mirror:

PORTGRID_REGISTRY_MIRROR=harbor.internal.corp:5000 portgrid up

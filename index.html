Less environment wrangling.

PortGrid brings the moving pieces around local services into one repeatable workflow, from launch and credentials to runtime visibility.

01 / Networking

Port-aware service setup

Keep engine and companion UI ports visible, with connection information presented alongside each installed service.

02 / Local runtime

Local-first by design

Develop against services running in your own environment, keeping the local feedback loop close to your code.

03 / Admin tools

Companion consoles

Pair supported services with web-based management tools so you can inspect and operate them without assembling every UI yourself.

04 / Configuration

Connection-ready configuration

Find service ports and copy useful connection values into the application you are developing.

05 / Operations

Runtime visibility

Use the control center and terminal log views to review service state and understand what a container is doing.

06 / Extensibility

Custom service workflows

Extend the catalog with container images, environment variables, persistent mounts, and optional companion interfaces.

Quickstart

From terminal to running service.

Start the local runtime, choose a blueprint, and connect your application with the generated service details.

01

Install the CLI

Install PortGrid globally with npm on a supported Node.js environment.

npm install -g portgrid-dev
02

Start your workspace

Bring up the local runtime and open the PortGrid control center.

portgrid up
03

Deploy and connect

Deploy a service blueprint and use its port and connection details in your app.

portgrid deploy postgresql
Read the full installation guide →
Connect your app

Bring local services into your code.

Use the environment values and connection strings from your PortGrid workspace. Examples below use placeholders; replace them with the credentials generated for your own service.

.env.example
# Replace with values from your PortGrid service
DB_HOST=127.0.0.1
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=${DB_PASSWORD}
DB_NAME=devdb
DATABASE_URL=postgresql://postgres:${DB_PASSWORD}@127.0.0.1:5432/devdb

REDIS_URL=redis://:${REDIS_PASSWORD}@127.0.0.1:6379
KAFKA_BOOTSTRAP_SERVERS=127.0.0.1:9092

Common questions

Good to know before you start.

A few quick answers about the PortGrid workflow.

How does PortGrid handle port conflicts?
PortGrid’s documented workflow checks port availability during service deployment and can use an available port when a default is occupied. Check the current blueprint and connection details for the effective port assigned to each service.
Does PortGrid require a hosted cloud account?
PortGrid is designed around a local development workflow. Consult the installation guide and product documentation for current runtime requirements and any optional network behavior.
Can I add my own container images?
The product documentation describes a custom service workflow for defining container images, environment variables, persistent mounts, and optional web interfaces. See the service catalog documentation for supported fields and current limitations.
Where can I verify security-related behavior?
Use the security documentation for precise implementation details, version-specific capabilities, and configuration requirements. Cryptographic or compliance properties should be evaluated against the implementation and its deployment context.
